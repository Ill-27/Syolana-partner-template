# Partner Site Template

Нейтральный шаблон отдельного партнёрского сайта.

## Принцип владения

Партнёр остаётся владельцем своего сайта и контента:

- его GitHub-репозиторий;
- его хостинг и домен;
- его публичная страница VK как единственный источник публикаций;
- его VK-токен хранится только в Secrets его репозитория;
- его контакты и данные проекта находятся в `partner.json`.

Опциональный иммерсивный слой подключается отдельно по лицензии. Премиальные темы, плеер, шрифты, аудио и runtime не должны копироваться в репозиторий партнёра.

## Публикации: только VK

Партнёр создаёт, исправляет и удаляет публикации только на своей публичной странице ВКонтакте.

Workflow `.github/workflows/sync-vk-feed.yml`:

1. использует `VK_OWNER_ID` из Repository Variables;
2. использует `VK_ACCESS_TOKEN` из Repository Secrets;
3. читает публичные записи через официальный VK API;
4. принимает только записи, автором которых является настроенный владелец/сообщество;
5. обновляет только производный `feed.json`.

В шаблоне нет отдельной редакции постов, загрузки медиа или API публикации со стороны платформы.

## Основные файлы

- `partner.json` — публичные данные и контакты партнёра;
- `feed.json` — производное отображение публичной VK-ленты;
- `scripts/sync-vk-feed.mjs` — синхронизация VK → feed;
- `scripts/build-feed.mjs` — проверка производной ленты;
- `studio/` — просмотр ленты и защищённые настройки контактов;
- `platform-loader.js` — опциональный лицензионный слой;
- `integration.json` — несекретная конфигурация подключения.

## Быстрый запуск

1. Партнёр создаёт свой репозиторий из подготовленной нейтральной копии.
2. Заполняет `partner.json`.
3. В Settings → Secrets and variables → Actions добавляет свой `VK_ACCESS_TOKEN`.
4. В Variables добавляет `VK_OWNER_ID`.
5. В Settings → Pages выбирает GitHub Actions.
6. Запускает `Sync public VK feed` один раз вручную; далее он синхронизируется по расписанию.

## Безопасность

Никогда не добавлять в файлы репозитория:

- VK access token;
- GitHub credential;
- ключ Partner Studio;
- entitlement service token;
- платёжные секреты.

Production-лицензия не должна опираться на публичный `entitlements.json`. Сервер лицензий должен проверять partner ID + hostname и отдавать короткоживущий доступ к премиальному runtime.

## Отключение

При отключённой лицензии публичный сайт партнёра продолжает показывать только его собственную нейтральную оболочку и VK-публикации. Опциональный платформенный слой не монтируется.

Удалённо стереть файл из чужого GitHub без доступа невозможно. Поэтому отдельный Detach остаётся лишь уборкой исходников, а не механизмом лицензирования.
