# Syolana Partner Template

Эталонный шаблон отдельного партнёрского сайта.

## Как устроена модель

Партнёр остаётся владельцем своего сайта и контента:

- отдельный GitHub-репозиторий;
- отдельный хостинг (GitHub Pages, Cloudflare Pages или другой);
- собственный домен — по желанию;
- собственные публикации и медиа;
- Syolana подключает темы, плеер, иммерсивные функции и обновления как отдельный слой.

Премиальные функции Syolana не копируются в репозиторий партнёра: активный сайт подгружает их из центрального Syolana Core. Сейчас шаблон уже умеет получать центральные стили, шрифты, баннер, темы, звуки тем, музыкальный плеер и режим созерцания; при обновлении Syolana они становятся доступны партнёрскому сайту без копирования файлов в его репозиторий.

## Структура

- `partner.json` — данные партнёра;
- `integration.json` — параметры центрального Syolana Core и лицензии;
- `posts/*.json` — отдельные публикации;
- `feed.json` — собирается автоматически;
- `index.html`, `app.js`, `styles.css` — сайт;
- `scripts/build-feed.mjs` — проверка и сборка ленты;
- `.github/workflows/validate-content.yml` — автоматическая проверка контента;
- `.github/workflows/deploy-pages.yml` — публикация на GitHub Pages;
- `docs/` — запуск, публикации и будущая лицензия.

## Автоматические обновления Syolana

`platform-loader.js` загружает актуальные ресурсы прямо из центрального репозитория Syolana с обновлением кэша при каждом новом открытии страницы. Поэтому обычные изменения тем, шрифтов, CSS, баннера, списка песен, звуков и самого `partner-core.js` не требуют коммита в каждый партнёрский репозиторий.

Собственный контент партнёра при этом остаётся локальным: `partner.json`, `posts/`, `feed.json`, медиа и домен не зависят от Syolana.

## Быстрый запуск

1. Создать новый репозиторий из этого шаблона.
2. Изменить `partner.json`.
3. Добавить публикации в `posts/`.
4. В GitHub открыть **Settings → Pages → Source: GitHub Actions**.
5. Дождаться workflow **Deploy partner site**.
6. При желании привязать собственный домен партнёра.

## Безопасность

В репозиторий нельзя добавлять пароли, API-ключи, платёжные токены и секреты лицензии. Секреты должны храниться только в Secrets выбранного serverless/edge-провайдера.

## Права и ответственность

Шаблон помогает технически разделить инфраструктуру: сайт, домен, хостинг и публикации находятся у партнёра. Это не отменяет применимое законодательство и договорные обязанности сторон; роли и права должны быть зафиксированы в условиях подключения Syolana.


## Отключение партнёра

Есть два уровня отключения:

1. Центральное отключение работает независимо от действий партнёра. Если доступ выключен, внешний слой не загружается: на публичной странице не остаётся баннера, тем, плеера, фирменных шрифтов, логотипов, рекламных объектов или видимого текста Syolana. Уже открытая вкладка повторно проверяет доступ и снимает слой автоматически.
2. **Detach optional platform layer** — только дополнительная очистка исходного кода репозитория. Она не нужна для прекращения показа Syolana. Если партнёр её не запускает, в его репозитории может остаться неактивный loader и техническая ссылка на endpoint, но они не должны показывать бренд или личные данные посетителю после центрального отключения.

Сайт, домен, публикации и медиа партнёра при этом сохраняются.


## Контакты партнёра

В `partner.json` предусмотрены три стандартных публичных контакта:

- Yandex-почта;
- ВКонтакте;
- Авито.

Пустые контакты не показываются. Как только партнёр указывает свой адрес/ссылку, сайт автоматически выводит красивую кнопку в блоке «Контакты проекта».
