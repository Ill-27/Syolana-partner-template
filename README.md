# Syolana Partner Template

Эталонный шаблон отдельного партнёрского сайта.

## Как устроена модель

Партнёр остаётся владельцем своего сайта и контента:

- отдельный GitHub-репозиторий;
- отдельный хостинг (GitHub Pages, Cloudflare Pages или другой);
- собственный домен — по желанию;
- собственные публикации и медиа;
- Syolana подключает темы, плеер, иммерсивные функции и обновления как отдельный слой.

Премиальные функции Syolana не копируются навсегда в репозиторий партнёра: позже они подключаются через лицензионный endpoint и короткоживущий доступ.

## Структура

- `partner.json` — данные партнёра;
- `syolana.json` — параметры подключения Syolana Core;
- `posts/*.json` — отдельные публикации;
- `feed.json` — собирается автоматически;
- `index.html`, `app.js`, `styles.css` — сайт;
- `scripts/build-feed.mjs` — проверка и сборка ленты;
- `.github/workflows/validate-content.yml` — автоматическая проверка контента;
- `.github/workflows/deploy-pages.yml` — публикация на GitHub Pages;
- `docs/` — запуск, публикации и будущая лицензия.

## Быстрый запуск

1. Создать новый репозиторий из этого шаблона.
2. Изменить `partner.json`.
3. Добавить публикации в `posts/`.
4. В GitHub открыть **Settings → Pages → Source: GitHub Actions**.
5. Дождаться workflow **Deploy partner site**.
6. При желании привязать собственный домен партнёра.

## Безопасность

В репозиторий нельзя добавлять пароли, API-ключи, платёжные токены и секреты лицензии. Секреты должны храниться только в Secrets выбранного serverless/edge-провайдера.

## Права и ответственность

Шаблон помогает технически разделить инфраструктуру: сайт, домен, хостинг и публикации находятся у партнёра. Это не отменяет применимое законодательство и договорные обязанности сторон; роли и права должны быть зафиксированы в условиях подключения Syolana.
