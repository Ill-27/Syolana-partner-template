# Публикации партнёра

## Целевая схема

Партнёр не должен ежедневно заходить в GitHub и не должен знать JSON.

Основной путь:

Partner Studio → защищённый российский Studio API → репозиторий партнёра → GitHub Actions → сайт

Альтернативный источник:

VK → официальный API VK → черновик → Partner Studio → публикация

## Что уже есть

- Partner Studio с созданием, редактированием, удалением и предпросмотром локальных черновиков;
- отображение опубликованных постов;
- поддержка изображений;
- публичные контакты партнёра: Yandex-почта, VK, Avito;
- автоматическая очередь черновиков из VK;
- автоматическая проверка публикаций;
- автоматическая сборка feed.json и деплой сайта.

## Почему публикация из браузера пока не пишет прямо в GitHub

GitHub write-token нельзя помещать в JavaScript публичного сайта. Его сможет извлечь любой посетитель.

Поэтому production Studio должен обращаться к защищённому serverless endpoint. Endpoint хранит GitHub credential только на сервере и проверяет партнёра до записи в репозиторий.

## Как партнёр будет работать

1. Открывает Partner Studio.
2. Авторизуется.
3. Нажимает «Новая публикация».
4. Вводит заголовок, категорию, текст.
5. Добавляет изображение.
6. Нажимает «Предпросмотр».
7. Сохраняет черновик.
8. Нажимает «Опубликовать».
9. Studio API создаёт или обновляет JSON/медиа в репозитории.
10. GitHub Actions проверяет данные и публикует сайт.

Редактирование — тот же экран.

Удаление — отдельная подтверждаемая команда Studio API.

## VK как источник черновиков

Импорт предназначен только для публичной стены/сообщества, которое контролирует партнёр.

Настройки репозитория:

- Repository variable VK_OWNER_ID — числовой owner_id;
- Repository variable VK_API_VERSION — версия API, если нужно переопределить значение по умолчанию;
- Repository secret VK_ACCESS_TOKEN — токен VK.

Workflow Import VK posts as drafts проверяет источник раз в час и создаёт только новые файлы в drafts/vk.

По умолчанию:

- импортируются только записи, где from_id совпадает с настроенным owner_id;
- личные сообщения и комментарии не читаются;
- новые записи становятся черновиками;
- публикация на сайт без подтверждения партнёра не происходит.

Перед публикацией удалённые изображения VK должны быть перенесены в media/ партнёрского репозитория, чтобы сайт не зависел от временной внешней ссылки.

## Модерация

Для снижения юридического и операционного риска базовый режим Syolana:

- автоматическая техническая проверка структуры;
- проверка размеров/типов файлов;
- без обещания предварительной юридической экспертизы каждого поста;
- возможность вручную отключить Syolana Core;
- notice-and-takedown при жалобах.

Если позже понадобится отдельная содержательная модерация, её можно включить как дополнительный режим, но это не должно быть условием работы каждого партнёрского сайта.

## Что никогда не хранить в браузере

- GitHub token;
- VK token;
- ключ Yandex Cloud;
- платежные секреты;
- приватный ключ GitHub App;
- пароль в открытом виде.
