# Публикации партнёра

## Целевая схема

Партнёр не должен ежедневно заходить в GitHub.

Финальная цепочка:

`Редактор на сайте → serverless endpoint → draft/PR → проверки → merge → GitHub Pages/Cloudflare Pages`

## Почему не отправлять GitHub-токен из браузера

GitHub write-token нельзя помещать в JavaScript сайта: его сможет получить любой посетитель.

Поэтому форма публикации должна обращаться к маленькому serverless endpoint, а уже endpoint — к GitHub API.

## Автоматическая модерация

Безопасная схема:

1. техническая проверка структуры;
2. проверка ссылок и размеров файлов;
3. автоматическая классификация очевидных нарушений;
4. нормальные посты — в PR/автопубликацию по выбранному режиму;
5. сомнительные — `needs-review`;
6. спорные решения может пересмотреть человек.

## Рекомендуемые режимы

### Новый партнёр

Все публикации создают PR и требуют одобрения.

### Проверенный партнёр

Технически корректные публикации могут публиковаться автоматически; спорные уходят на проверку.

## Роль Syolana

Syolana предоставляет инструменты публикации и правила платформы. Владельцем сайта и исходного материала остаётся партнёр.
