# Production backend для Partner Studio — схема РФ

## Задача

Дать Partner Studio право создавать, редактировать и удалять посты без выдачи партнёру GitHub-токена и без хранения серверных секретов в браузере.

## Рекомендуемая архитектура

Для коммерческого запуска:

Browser Partner Studio → HTTPS API Gateway → российская serverless function → GitHub API

Первичная аутентификация и журналы безопасности должны проектироваться с учётом требований РФ к персональным данным.

В качестве первого кандидата можно использовать российскую serverless-инфраструктуру, например Yandex Cloud. Бесплатность не обещать: перед запуском проверить актуальные тарифы и лимиты.

## Минимальные серверные секреты

- GITHUB_REPO — конкретный repo партнёра;
- GITHUB_APP / fine-grained credential — только права на этот repo;
- SESSION_SECRET — подпись коротких Studio-сессий;
- PARTNER_ACCESS_KEY_HASH или иная серверная схема входа;
- ALLOWED_ORIGIN — точный домен Studio.

Никакой секрет не возвращается в браузер.

## API

POST /session

Вход партнёра. Возвращает короткоживущий HttpOnly/SameSite session cookie или эквивалентную защищённую сессию.

GET /posts

Возвращает список опубликованных постов и черновиков текущего партнёра.

POST /posts

Создаёт новый пост после проверки схемы.

PUT /posts/:id

Редактирует существующий пост.

DELETE /posts/:id

Удаляет пост только после отдельного подтверждения.

POST /media

Принимает изображение с ограничением размера/типа и помещает его в media/.

GET /vk-drafts

Возвращает черновики из drafts/vk.

POST /vk-drafts/:id/publish

Переносит выбранный черновик VK в обычный пост, предварительно сохранив нужные изображения в media/.

## Защита

- CORS только для домена партнёра;
- короткие сессии;
- CSRF-защита, если используется cookie;
- rate limiting;
- ограничение размера body и файлов;
- allowlist MIME;
- безопасные имена файлов;
- никакого HTML из формы без очистки;
- журнал действий: create/update/delete/publish;
- GitHub credential с минимальными правами;
- отдельный credential на каждого партнёра или GitHub App с установкой только на его repo;
- немедленная инвалидизация сессий при отключении партнёра.

## Отключение

Центральный Syolana entitlement остаётся отдельным от Studio.

Даже если автоматическая оплата появится позже, ручной административный переключатель всегда остаётся приоритетным: Syolana может выключить core и Studio для конкретного partnerId.
