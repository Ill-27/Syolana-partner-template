# Partner Studio API — production boundary

Этот серверный шлюз больше не публикует и не хранит посты партнёра.

Публикации имеют один источник истины: публичную страницу партнёра во ВКонтакте.
Синхронизация выполняется внутри репозитория партнёра workflow `sync-vk-feed.yml`.
VK-токен хранится в GitHub Secrets самого партнёра и не передаётся Syolana.

## Что делает Studio API

- POST /session — создаёт короткую серверную сессию партнёра;
- GET /status — возвращает лицензионный статус и доступные функции;
- GET /contacts — читает публичные контакты партнёра;
- PUT /contacts — обновляет только контакты в `partner.json`.

Здесь намеренно нет:

- создания постов;
- редактирования постов;
- удаления постов;
- загрузки медиа;
- VK-токена;
- API для публикации контента.

## Переменные окружения

- PARTNER_ID
- PARTNER_ACCESS_KEY_HASH — SHA-256 партнёрского ключа;
- SESSION_SECRET — длинный случайный секрет подписи сессий;
- ALLOWED_ORIGIN — точный HTTPS origin Partner Studio;
- ENTITLEMENT_URL — приватный production endpoint лицензий;
- ENTITLEMENT_SERVICE_TOKEN — service-to-service токен для entitlement;
- GITHUB_REPO — owner/repo конкретного партнёра;
- GITHUB_TOKEN — fine-grained credential только для изменения `partner.json`.

Секреты вводятся только в панели serverless-провайдера. Их нельзя помещать в публичный репозиторий, Studio config или браузер.

## Production

Перед коммерческим запуском:

- entitlement должен жить на приватном сервере, а не в публичном JSON;
- добавить rate limiting и журнал действий;
- инвалидировать сессии при disable партнёра;
- ограничить GitHub credential минимальными правами;
- перейти на GitHub App вместо отдельных PAT при росте числа партнёров;
- хранить первичную аутентификацию и журналы в выбранной инфраструктуре с учётом фактических требований к персональным данным.

## Почему публикации вынесены из Syolana

Так Syolana технически не является редактором партнёрского контента: партнёр публикует, исправляет и удаляет материал на своей публичной странице VK, а его собственный репозиторий лишь создаёт производный публичный `feed.json` для отображения на его сайте.
